Hit bad cell        : 0.0%
Avg steps           : 3.44
PI iterations       : mean=4.80  min=3  max=8  (distribution: {3: 52, 4: 327, 5: 419, 6: 172, 7: 28, 8: 2})
Planning time / maze: 0.86 ms

The code uses vectorized NumPy and plans once per layout (cached). 
It does not start every sweep from zero, since evaluation is warm-started from the previous V.
Considering it's just a 5 * 5 matrix, it's feasible, 
but if we scale the matrix, it will become computationally expensive to compute or cache it.

Q5: Can policy itera􀆟on work on a 100x100 maze? Explain why?
It takes a lot of time to compute, it has scalability issues.
python main.py --eval 1000 --size 100
Episodes            : 1000
Reached goal        : 100.0%
Hit bad cell        : 0.0%
Avg steps           : 63.80
PI iterations       : mean=45.62  min=32  max=62  (distribution: {32: 3, 33: 5, 34: 14, 35: 17, 36: 22, 37: 30, 38: 27, 39: 35, 40: 39, 41: 53, 42: 60, 43: 46, 44: 57, 45: 82, 46: 55, 47: 63, 48: 71, 49: 79, 50: 43, 51: 45, 52: 40, 53: 30, 54: 32, 55: 12, 56: 19, 57: 4, 58: 10, 59: 4, 60: 2, 62: 1})
Planning time / maze: 137.75 ms


It works only because the layout is fixed and known. 
Planning over every possible layout would not fit in memory, 
and the exact linear solve scales as O(n³).

Q6: Can policy itera􀆟on work on a con􀆟nuous-space maze? Explain why?
Policy Iteration is tabular, so it cannot enumerate infinitely many states. 
You would need discretization or function approximation.

Q7: Can policy itera􀆟on work with moving bad cells (like Packman moving ghosts)? Explain why?
The state would have to include the ghosts’ positions, so the state space grows exponentially. 
If the ghosts move randomly you also need a probabilistic transition model.
